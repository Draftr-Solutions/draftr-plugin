# Draftr editing rules

Generated from the instructions of the Draftr MCP server by `pnpm sync:rules`. Do not edit.

- Draftr is a structured UI design editor.
- Read a document before editing.
- Start an agent task before making a related group of edits, pass its taskId to apply_commands, and record the result with complete_agent_task. People in the editor see you in presence with the task title and the layers your last change touched, until you complete the task.
- A task with no changes for 1 hour ends as failed and keeps its changes; start a new task to continue.
- Comments: people leave feedback in threads pinned to layers, areas or points. list_comments shows open threads with where they are now; change the design, answer with reply_comment saying what you changed, and resolve_comment when the feedback is addressed. add_comment starts a thread, for example to ask a question about a layer.
- Prototypes: layers hold prototype {interactions} and top-level frames may start a flow with prototypeStart {name}; get_prototype describes the graph and the interaction format. Link buttons to screens with navigate, menus and dialogs with open-overlay, and give every flow a start.
- Interactive prototypes: update_prototype changes interactions, fields, scroll containers and fixed or sticky layers of several layers at once. Make interactive components by putting change-to interactions inside each variant (targetId null), give form fields a component with State default, focus and error plus input rules, and end a form with submit. Starter blocks mobile-menu, sign-up-flow and product-carousel show the patterns.
- Motion: update_prototype sets motion on layers (keyframes of opacity, x, y, scale and rotate; started with the screen, when the layer appears or by scroll) and transitions take smart animate and cubic-bezier or spring easing. Name layers alike on both screens or variants so smart animate pairs them. get_prototype_frame draws a screen at a moment (time, variants, scroll, reduced motion) to check motion without Play.
- Apply atomic commands using the current baseRevision and a unique operationId.
- Retry the identical operationId only with the identical request after network failures.
- Authored coordinates are parent-local; auto-layout derives positions and sizes. read_nodes and find_nodes expose computed world-space bounds.
- Icons and SVG: search_icons finds built-in Phosphor icons and insert_icon adds one as an editable frame of vectors in a size and color; import_svg turns SVG text into editable layers and reports what it skipped (text, images, use, clip paths, masks, filters, CSS). Prefer them over drawing icons point by point.
- Personal library: list_library_assets searches the account library of images (PNG, JPEG, WebP with alpha) and SVG files by name and tags; upload_library_asset adds one; insert_library_asset copies an item into a design (an image as a rectangle with a Fit fill, an SVG as editable layers). Designs never reference the library, so deleting an item changes no design. replace_image swaps one image asset for another across fills, component image properties and instances.
- Responsive breakpoints: a frame on a page or in a section may hold breakpoints, 1-8 entries {id, name, width, overrides}, sent complete with node.update. overrides maps the frame or a layer in it to changes of x, y, width, height, visible, fontSize, layout, layoutSizing (including grid placement) and transform (rotate, flip or scale a layer on that screen only, for example a device mockup wider than the screen; null is identity, and layout measures before the transform); everything else, order and content are shared. The frame takes the breakpoint width, its own override has no width, x or y, and auto layout cannot be switched off in a breakpoint. Typical sets are the base at 1440, tablet 768 and mobile 390: collapse grid columns, hide decorations and shrink headings in the overrides. get_design_screenshot, export_design and read_nodes take breakpoints {frameId: breakpointId} to show frames at a breakpoint; read_nodes then returns the layers with the overrides applied.
- Starter blocks: list_blocks lists built-in blocks: landing (navigation, hero, features, bento, pricing, sign-up form, footer), mobile at 390 wide (status bar, header, tab bar, settings list, onboarding; put the status bar at the top of every phone screen), commerce (product grid as a collection list, product detail, cart summary) and devices (phone, browser window, laptop). insert_block adds one as ordinary editable layers bound to shared starter tokens such as color/primary and radius/medium, which it creates when missing. Stack blocks in a column auto-layout frame to start a page fast, then edit copy, images and tokens. Upload a screenshot with upload_document_asset and pass screenshotAssetId to show it in a device mockup, or set an image fill on its Screenshot layer later.
- Collections and lists: for product cards, reviews, pricing plans and logo grids, store the data once and repeat a component. {type: collection.set, collection: {id, name, fields: [{id, name, type: text|boolean|image}], rows: [{id, values: {fieldId: value}}]}} creates or replaces a collection (up to 30 fields and 200 rows; image values are document image asset IDs; a missing or null value takes the component property default). A frame with auto layout becomes a list with node.update patch {repeat: {collectionId, componentId, mapping: {propertyId: fieldId}}}, mapping component properties to fields of the same type. {type: collection.apply, nodeId} then creates, updates and deletes ordinary instances so each row has one, marked instance.collectionRow; re-apply after every collection.set. Overrides and unmapped property values of row instances survive. Bind optional badges to boolean properties and let text hug so cards take different text lengths. {type: collection.delete, collectionId} unlinks its lists and leaves their instances.
- Layout grids: a frame may hold layoutGrids, up to 10 complete entries: columns or rows {id, type, visible, color (hex, usually with alpha), count 1-100, gutter, offset, alignment stretch|start|center|end, size} and square grids {id, type "grid", visible, color, size}. They are design guides that screenshots and exports never draw; people snap to them in the editor. read_nodes returns layoutGridTracks per frame: the column and row tracks {start, end} in frame-local coordinates, so children placed at those x/y and widths line up with the columns. Stretch tracks follow the frame width, also at breakpoints. Use a 12-column grid with gutters and margins on desktop screens and 4 columns on mobile.
- Grid frames: layout {direction "grid", columns: tracks, rows: tracks, autoRows: track, columnGap, rowGap, padding, align and justify start/center/end}. A track is {type "fixed", size}, {type "fill", weight like fr, min?, max?} or {type "hug", min?, max?}; rows past the explicit ones take autoRows, and there are no implicit columns. Flow children fill cells row by row in layer order; layoutSizing.grid {column, row, columnSpan, rowSpan} (1-based) places one. A child that fills an axis fills its cell area; fixed and hug children align inside it. Use grids for card grids, pricing tables and dashboards, and nest row or column frames inside cells.
- Nodes support ordered solid, gradient, image and grain fills, document font asset references, strokes, frame/rectangle corners and ordered drop-shadow, inner-shadow, layer-blur and background-blur effects.
- Grain: a fill {id, type: "noise", visible, opacity, blendMode?, size 0.5-16 (grain in layer units), seed 0-1000000, monochrome} adds deterministic film grain. Put it as the top fill of a dark or gradient background at 0.04-0.12 opacity with blendMode overlay or soft-light. Text cannot take grain; vector exports rasterize the layer.
- Image placeholders: when a design needs a photo, render, logo or screenshot you do not have, make a frame, rectangle, ellipse, polygon, star or vector of the right size and shape with placeholder {label, prompt?}: label names the picture ("Hero device collage"), prompt describes it for an image generator (subject, composition, light, colors, style, aspect). The layer draws a neutral surface (or its own fills), a picture icon and the label until an image fills it, so screenshots show where pictures go. list_placeholders lists them; fill_placeholder puts an uploaded asset in (or takes it out with assetId null); a person fills one in the editor by clicking or dropping a file. Never fake a photo with flat shapes when a placeholder fits.
- Recreating a reference (a screenshot or design to match): upload it with upload_document_asset, set the frame reference {assetId, opacity, mode overlay|difference, visible} so people can check it in the editor (only the editor draws it), size the frame to the reference width, then call compare_with_reference after each round of changes. Work on its worstRegions first and stop when both similarities stop rising; put photos the reference shows in placeholders rather than drawing them.
- Text has optional atomic textStyle: align left/center/right/justify, verticalAlign top/middle/bottom, lineHeight in px or null for 140% of fontSize, letterSpacing in px, decoration none/underline/line-through/underline-line-through, wrap word/none, direction ltr/rtl, and optional textCase none/upper/lower/title, which shows the text cased without changing it (type the text normally and set textCase for labels and headings in capitals).
- Supply the complete textStyle object or null to reset.
- Text sizing uses layoutSizing: width hug with height hug is auto width; fixed or fill width with height hug is auto height, wrapping at the box width; any other text is a fixed box whose overflow is clipped.
- Auto width does not wrap at a row or start/center/end column width; a stretch column stretches it to the column width, where textStyle wrap word wraps it, and with wrap word layoutSizing maxWidth also wraps it.
- Stored width/height of hug axes are positive fallbacks, not measured sizes; read real sizes from read_nodes or find_nodes bounds.
- To give auto-width text a fixed width, send its complete layoutSizing with width "fixed" and height "hug" (keep position and any min/max) plus width in one patch; switching a text axis out of hug without a size keeps its visible size.
- Text is measured with its referenced font; when measurement is unavailable the request fails with TEXT_MEASUREMENT_UNAVAILABLE and nothing is saved.
- Each font asset is one face; its fontFace reports family, style, weight 1-1000, italic and variable, or null for a legacy upload not scanned yet.
- Choose a face by fontAssetId: to use a weight or italic, set fontAssetId to the asset with that face. A null fontAssetId uses the built-in Noto Sans Regular 400.
- Bold and italic are never synthesized. Variable fonts render the axis values of fontVariations, up to 8 {tag: value} such as {"wght": 650, "wdth": 112} on a text layer or range; without them a variable font draws its default instance.
- Font catalog: list_fonts lists 34 built-in OFL families (sans such as Inter, Manrope, Geist and Space Grotesk; serif such as Playfair Display, Fraunces and Instrument Serif; display such as Bebas Neue, Anton and Archivo, whose wdth axis gives extended and condensed widths; mono such as JetBrains Mono and IBM Plex Mono; handwriting). Every document can use them without uploading: set fontAssetId to a catalog face id (catalog-...) and fontVariations to values inside its axes, for example wght from a named instance. Match a reference by choosing the closest catalog family, weight and width; upload a font only when the catalog has nothing close.
- Mixed styles: a text layer may hold textRuns, up to 1000 sorted, non-overlapping ranges {start, end, ...style} with UTF-16 offsets into text. A range overrides any of fontAssetId (a face, or null for the default font), fontSize, fill (a solid or gradient paint without id or token, in the layer box), highlight (hex background color), decoration, decorationStyle solid/double/dotted/dashed/wavy, decorationColor (hex, else the range fill), letterSpacing, wordSpacing (applies between words inside the range) and lineHeight; alignment, wrap and direction stay on textStyle. Send the complete textRuns array or null to clear. A patch that changes only text keeps the ranges: core moves them, and typed characters take the style of the character before them. Use one text layer with ranges for a sentence with a bold word or a colored link instead of several text layers.
- Use list_document_assets and read_document_asset before referencing image or font IDs.
- Images are cropped from immutable originals; fonts require license metadata.
- Image fills: mode fit, fill, crop (scale 1-20 zooms in) or tile (the image repeats, one image pixel covering scale units, 0.05-20; position places one tile like fit). Optional adjustments {exposure, contrast, saturation, temperature, tint}, each -1 to 1 with 0 unchanged, sent complete or null; they never change the asset or its alpha. saturation -1 is grayscale, temperature above 0 is warmer, tint above 0 is magenta.
- Uploads are bounded by per-file and document storage limits.
- Strokes have width, inside/center/outside alignment, independent sides and optional dash/gap.
- Fills, strokes, effects, corners, transform, layoutSizing, mask, arc and path are complete atomic properties; retain existing entries when editing.
- Effects preserve their array order and visibility. Shadows use color, opacity, X/Y offset and blur; blur effects use a radius.
- Transform is a/b/c/d about normalized originX/originY (default center); null means identity.
- For clockwise angle r and signed scales sx/sy use a=cos(r)*sx, b=sin(r)*sx, c=-sin(r)*sy, d=cos(r)*sy.
- Layout measures before transform; scale includes descendants, text, fills, strokes and clips.
- Shapes: besides frame, rectangle and text, nodes may be ellipse, polygon, star, line or vector. An ellipse fills its box; optional arc {start, sweep, innerRatio} in degrees clockwise from the positive X axis (sweep -360..360, not 0; innerRatio 0..0.99) makes pie slices and rings. A polygon takes pointCount 3-60 and a star pointCount plus innerRatio 0.01-1; their vertices lie on the ellipse inscribed in the box, the first on top.
- A line runs from (0, 0) to (width, 0) of its box and always has height 0; set its direction with transform, for example a = cos(r), b = sin(r), c = -sin(r), d = cos(r) with originX 0 and originY 0, and give it a center stroke.
- A vector has path {fillRule: nonzero|evenodd, contours: [{closed, points: [{x, y, in?, out?}]}]}: points and their Bezier handles are normalized to the box (0..1, within +/-8), so resizing changes only width and height. Use convert_svg_path to turn SVG path data into the box and path of a vector node.
- Strokes take optional cap butt|round|square, join miter|round|bevel and miterLimit 1-100 (defaults butt, miter, 4). Lines and vectors with an open contour accept only center strokes, only rectangles and frames can stroke some sides, and fills of an open contour close it implicitly. Polygon and star corners use one radius for every vertex; ellipses, lines and vectors take no corners, and lines take no inner shadow or background blur.
- Boolean groups: a node of type boolean with booleanOperation union, subtract, intersect or exclude combines the outlines of its children (rectangles, ellipses, polygons, stars, vectors and nested boolean groups; not text, frames or lines). Subtract keeps the bottom child minus the others; exclude keeps areas covered an odd number of times. The children are not painted: the result takes the group fills, strokes, effects, opacity and blend mode, and hidden children are ignored.
- To combine layers, node.create the boolean group in their parent, then node.move the layers into it (they keep their world position); children of a boolean group cannot be masks, and a group can be neither a mask nor rounded. Flattening a group into a vector is an editor action, not available over MCP.
- Design tokens: a document may hold tokens {id, name, type: color|number, value, description?} with unique names; slashes group them, as in color/brand/primary. Read them with get_document. Create or replace a token with the command {type: token.set, token} and delete it with {type: token.delete, tokenId} in apply_commands, next to node commands.
- Bind a solid fill or stroke paint to a color token with token: <id>, and a layer to number tokens with tokenBindings {opacity, cornerRadius, gap, padding, fontSize}. The binding wins: bound fields always take the token value, also after you change the token, so remove the binding to use another value. Deleting a token keeps the values and drops its bindings.
- Token aliases and modes: a token may set alias: <id> of a token of the same type and then always takes its values; core writes the resolved value, so do not compute it. Define modes such as Light and Dark with {type: token.mode.set, mode: {id, name, scheme: light|dark}} (the scheme lets Play start in the theme of the viewer) (the first mode is the default and names value) and give tokens modeValues {<modeId>: value} for the other modes. A frame sets tokenMode: <modeId> for itself and everything inside it; bound layers then take the values of that mode, which lets light and dark screens sit side by side. In Play, a set-mode interaction {modeId: null} toggles every screen to the next mode, a theme switch. {type: token.mode.delete, modeId} removes a mode.
- Styles: a document may hold styles {id, name, type, description?} with unique names. A text style has fontSize, fontAssetId (a document font asset or null), lineHeight (null for automatic) and letterSpacing; an effect style has effects in the shape of layer effects. Create or replace one with {type: style.set, style} and delete it with {type: style.delete, styleId}. Bind a layer with styleBindings {text: <id>} (text layers only, not together with a fontSize token) and {effect: <id>}. The binding wins like token bindings: the layer always takes the style values, so remove the binding to change them on that layer alone. Prefer styles over copying the same typography or shadows onto many layers.
- Components: make a frame a main component with node.update {component: {}} and reuse it with node.create of a frame {instance: {componentId, overrides: {}}, children: []} at its own position and size. Core builds the instance layers with IDs <instanceId>--<componentLayerId> and marks them with instanceLayer; read them with get_document. To change one instance, node.update its instance layer (or the instance root) with text, textRuns, fill, fills, strokes, effects, visible, opacity, blendMode, fontSize, fontAssetId, textStyle, corners, tokenBindings or styleBindings; core stores that as an override. To change every instance, edit the component. Instance layers cannot be created, deleted, moved or resized; detach with node.update {instance: null} first. {instance: {componentId, overrides: {}}} resets overrides; {component: null} releases a component and detaches its instances. Components cannot contain main components.
- Nested instances and properties: a component may contain instances of other components (never of itself, directly or through others); an outer instance copies the nested layers with IDs <outer>--<nested>--<layer> and overrides them like its own. Define named settings on a component with component.properties {<propertyId>: {name, type: text|boolean|image, default}} and bind component layers with propertyBindings {text: <propertyId>} on text, {visible: <propertyId>} on any layer or {image: <propertyId>} on a layer with an image fill. Instances set values with instance.properties {<propertyId>: value}; a missing value uses the default. Prefer properties over layer overrides for content that changes per instance, such as labels, icons and pictures. Editing the text or visibility of a bound instance layer sets the property.
- Variants and states: a frame with componentSet: {} groups variant components; each child is a component with component.variant {<variantProperty>: <value>}, all with the same variant properties and different values. The variant property State is reserved for visual states default, hover, focus, disabled, loading and error; states only change the design and run no application logic. Switch an instance with node.update {instance: {componentId: <other variant of the same set>, overrides: {}}}; core carries overrides over by layer name path and property values by property name. The apply_commands result adds a notice when some overrides match no layer of the new variant and are dropped. Create a variant by creating a component inside the set with its own layers and variant values.
- Pages: a document has 1-100 pages {id, name, rootIds} in order; get_document returns them all and every top-level node belongs to one page. get_design_screenshot, find_nodes and get_design_context require pageId and see only that page. Name pageId in node.create of a top-level node and in node.move with parentId null (it may move a layer to another page). Add or rename a page with {type: page.set, page: {id, name}}, reorder with {type: page.move, pageId, index} and delete one with its layers with {type: page.delete, pageId}; the last page cannot be deleted. Prefer one page per flow or breakpoint set and frames as screens on it.
- Sections: a section (type section) is a named region of a page with fill or fills that holds frames, other sections and any layers, with coordinates relative to it; it never clips or lays out its content. A section sits on a page or inside another section, never inside a frame or boolean group, and keeps only name, box, fill/fills, visible and locked (opacity 1). Use sections to group the screens of one flow; read their bounds with find_nodes and pass them as a screenshot region. Section names are editor labels and never appear in screenshots.
- Device viewports: a frame on a page or in a section may store viewport {preset, width, height, safeArea {top, right, bottom, left}}, the device screen it is designed for. preset is one of iphone-se (375x667), iphone-15 (393x852), iphone-15-pro-max (430x932), pixel-8 (412x915), galaxy-s24 (360x780), ipad-mini (744x1133), ipad-pro-11 (834x1194), laptop (1280x800), desktop (1440x1024), desktop-hd (1920x1080) or null for a custom size. For a screen, create the frame at the preset size with its viewport; it may grow taller for scrolling content, and viewport.height marks the fold. Keep content clear of the safe area. Viewports, bezels and safe areas never appear in screenshots; capture the first screen with a region of the viewport size.
- Export: export_design returns PNG, SVG or PDF files of a page (one per top-level frame and section) or of chosen layers (one file of them alone), at scale 0.1-4 and on a transparent or colored background. SVG and PDF files are vectors with text as outlines; they list any layer drawn as a PNG island. A PDF holds every exported frame as a page of one file. Use it to deliver finished screens; use get_design_screenshot to check your work in context.
- Guides and proportions: a document may hold ruler guides {id, axis: x|y, position} in page coordinates; axis x is a vertical line at that x. Read them with get_document and align layers to them; add or move one with {type: guide.set, guide} and remove it with {type: guide.delete, guideId}. Guides never appear in screenshots. A layer with constrainProportions: true keeps its aspect ratio: when you change only its width or only its height, core scales the other side, unless that side hugs or fills; set both to change the ratio.
- Masks: any layer except a frame or a boolean group (a shape, vector or text) with mask {"mode":"alpha"} or {"mode":"luminance"} is a mask layer. It is not painted, and it limits every other child of its parent frame, whatever the layer order; mask null or no mask makes it an ordinary layer again.
- An alpha mask shows content where its fills, strokes or glyphs are opaque; a luminance mask uses their brightness times alpha, so white shows and black hides. The mask opacity scales the mask and a layer blur feathers its edge.
- Several visible masks in one frame intersect, and masks nest through nested frames. A hidden mask is ignored; a mask with opacity 0 hides the other children of its frame. The frame itself (fills, strokes, effects) is never masked.
- Masks must be inside a frame: creating or moving a mask to the page fails with INVALID_PARENT, and giving a page-level layer a mask fails with INVALID_DOCUMENT. Any layer except a frame or boolean group can be a mask, its effects may only be layer blur (no shadows or background blur), and a document holds at most 1,024 masks.
- Inside an auto-layout frame a mask is always absolute and takes no flow slot: the server sets layoutSizing position absolute when a mask is created or moved there, when a flow layer becomes a mask (it keeps its displayed box) and when layout is enabled; a patch that gives a mask a flow position is rejected.
- Frames clip their children to their contour unless clipContent is false; then children and their effects may overflow, while the frame fills stay within its corners.
- To mask some layers, give them a frame of their own (a mask group) with fills [] and clipContent false, sized to the mask, in one apply_commands batch: node.create the frame, node.create or node.move the layers into it (node.move keeps their world position), then create the mask layer in it or node.update one of the moved rectangles or text with mask. Nest a second mask group inside to combine masks.
- Unlike Figma, the order inside the frame does not matter: layers below the mask are masked too, and several masks in one frame intersect instead of starting new mask ranges. Frame and group masks and inverted masks are not available.
- Blend modes: a layer takes blendMode, and every fill and stroke paint takes blendMode: normal, darken, multiply, color-burn, lighten, screen, color-dodge, overlay, soft-light, hard-light, difference, exclusion, hue, saturation, color or luminosity. Frames also take pass-through, their default; other layers and paints default to normal, and null restores the default.
- A pass-through frame lets its children and paints blend with what is beneath the frame, also under frame opacity. A frame with blendMode normal is isolated: its children blend only with each other. Any other layer mode draws the whole layer (shadows, fills, children, strokes) and blends the result with what is beneath at the layer opacity; its content is isolated too.
- A fill or stroke mode blends that paint with the fills below it on the same layer and with the layers beneath. Shadows always composite normally, background blur of an isolated layer blurs the real background, and a mask layer keeps its blendMode but does not apply it while it is a mask. Rectangles and text reject pass-through with INVALID_COMMAND.
- Blend modes follow the W3C compositing formulas in sRGB; exact Figma color parity, plus darker and plus lighter are not available. Check the result with get_design_screenshot.
- read_nodes and find_nodes bounds are layer boxes that ignore clipping and masks; check what is visible with get_design_screenshot.
- Manual node.move preserves the complete world transform, including shear; flow destinations reflow.
